# Selección de casos de validación

## Regla principal

Seleccionar casos por criterios documentales definidos **antes** de calcular la relación.

Nunca seleccionar un caso porque “parece tener aspectos interesantes”.

## Inclusión pública mínima

Para un caso real:

- datos natales públicos con procedencia;
- calidad horaria documentada;
- naturaleza de la relación públicamente verificable;
- cronología básica suficiente para la fase documental;
- ausencia de uso previo del caso para ajustar la versión a validar.

## Exclusión

Excluir de holdout:

- cualquier caso privado;
- casos usados durante el desarrollo de la regla;
- casos cuya hora natal fue elegida/rectificada para mejorar la firma;
- casos seleccionados después de ver sinastría o resultados;
- casos cuya única fuente sea una página SEO o una autoetiqueta;
- casos donde no pueda separarse hecho de interpretación.

## Blindaje

El selector puede conocer los requisitos documentales pero no debe seleccionar por resultado astrológico.

El analista estructural no recibe inicialmente:

- etiquetas soulmate/twin-flame;
- desenlace de la relación;
- narrativa de “destino”;
- sincronías subjetivas;
- interpretaciones de terceros.

## Balance

La cohorte debe contener suficientes controles para que una regla no sea evaluada sólo en relaciones famosas/intensas.

## Contaminación

Si durante la validación se descubre que un caso fue usado antes para diseñar una regla:

`EXTERNAL_HOLDOUT → RETIRED`

o, si sigue siendo útil:

`EXTERNAL_HOLDOUT → DEVELOPMENT_ONLY`.

No se sustituye silenciosamente por otro caso después de ver resultados.
